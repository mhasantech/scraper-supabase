# StockPulse Scraper — Supabase Primary + Firebase User Backup

StockPulse uses **Supabase as the primary database** and **Firebase Authentication** for login/authentication.

## Backup policy

Firebase Firestore is used only as a backup/fallback for user/business data:

- `user_registry`
- `user_meta`
- `subscriptions`
- `portfolios`
- `sales_history`
- `dividend_records`
- `admin_users`

The backup intentionally does **not** copy stock-price/history data such as:

- `dse_live_data`
- `daily_closing_prices`
- `cse_market_data`
- `dsex_index`
- `market_summary`
- `history_dse`
- `stock_metadata`

Market data remains in Supabase and can be scraped again from the source when needed.

## GitHub Secrets

Set these repository secrets:

- `SUPABASE_URL`
- `SUPABASE_SERVICE_KEY` — Supabase server/secret key only; never expose it in the frontend.
- `FIREBASE_SERVICE_ACCOUNT_KEY` — complete Firebase Admin SDK service-account JSON.

## Backup

Daily scheduled backup:

```bash
npm run backup:firebase
```

Manual full user/business backup:

```bash
BACKUP_MODE=full npm run backup:firebase
```

Both modes intentionally skip market-price/history tables.

## One-time legacy cleanup

The previous backup implementation may have created old market-data collections in Firestore. If those old copies are no longer needed, run:

```bash
npm run cleanup:firebase-market-backups
```

This deletes only these old collections:

- `backup_dse_live_data`
- `backup_daily_closing_prices`
- `backup_cse_market_data`
- `backup_market_summary`
- `backup_dsex_index`
- `backup_stock_metadata`
- `backup_history_dse`

Do this only after confirming the old market-data backups are no longer required.

## Pre-calculated indicators
`precompute_indicators.js` reads `history_dse`, calculates the latest technical-indicator snapshot for each ticker, and stores it in `stock_metadata.indicators`. It also keeps `stock_metadata.rsi` and `stock_metadata.psar` populated for compatibility. The app reads this snapshot first for fast scanner/indicator results and falls back to historical calculation only when the snapshot is unavailable.

Run once in Supabase SQL Editor:
`stock_metadata_migration.sql`

## DSE history + index scraper (fixed)

The historical updater no longer depends on `bd-stock-api-an3n.vercel.app`. It installs `bdshare`, fetches DSE historical OHLCV data with retry/fallback support, and writes normalized rows into `history_dse`. The updater refreshes the last 7 days on every run so a partially missed ticker/day can be repaired.

The DSEX updater no longer renders `/markets` in Chromium. It reads DSEX, DSES and DS30 from DSE's server-rendered **Recent Market Information** table and calculates daily absolute/percentage changes from consecutive DSE index values.

Run `stockpulse_history_constraints.sql` once in Supabase SQL Editor before the first fixed history run. This creates the `(ticker,date)` unique index required for safe PostgREST upserts.

Python requirement for history updater:

```bash
pip install -r requirements.txt
node scripts/update_dse_history.js
```


## Stability updates
- Market Summary parser reads the full rendered page rather than truncating at a guessed section boundary.
- Chrome render timeout and virtual time budget were increased for GitHub-hosted runners.
- Supabase upserts retry transient network, rate-limit, and server errors with bounded backoff.
- Scheduled market-summary frequency is reduced to avoid duplicating every price scrape run; daily closing now has its own independent scheduled workflow.
- The CSE, DSE prices, index, summary, history/indicator, and closing-price jobs can be run independently from the manual `Full Refresh` workflow.
- No scraper can guarantee that an external exchange site will never change; review GitHub Actions logs after the first run. Never add secrets to source files; use repository Actions secrets.
- `portfolios`, `sales_history`, `dividend_records`, `subscriptions`, `user_registry`, `user_meta`, and `admin_users` are app/user data tables and are not generated by market scrapers. The Firebase workflow backs up the designated user/business tables only.

## Market summary scraper (DSE)

`scripts/market_summary_scraper.js` reads the DSE market summary in this order:

1. `https://old.dsebd.org/` (primary): plain HTTP first, Chromium as backup. Parsed by `scripts/lib/dse_legacy.js`.
2. `https://new.dsebd.org/` (fallback): rendered with Chromium.

- The market date stored is the date printed on the DSE page ("Last update on Oct 15, 2026 ..."), not the date the job ran, so runs on Friday, Saturday or holidays update the real trading day.
- If every source fails, the job fails with one error that lists each attempt, and the fetched pages are uploaded as the `market-summary-debug` artifact (Actions run page, Artifacts section).
- Offline check of the legacy parser: `npm run test:dse-legacy`.

## Daily closing fundamentals

`scripts/update_daily_closing.js` adds `eps`, `pe_ratio`, `dividend`, `record_date` and `category` from the latest `cse_market_data` day to today's `daily_closing_prices` rows. DSE prices written by `dse_scraper.js` are never overwritten.


## DSE historical dividend scraper

The `scripts/dse_dividend_history_scraper.js` job reads each ticker's legacy DSE company page
(`https://old.dsebd.org/displayCompany.php?name=TICKER`) and upserts historical cash/stock
dividend percentages into `public.dse_dividend_data`. Run `supabase_dse_dividend_data.sql`
once in Supabase SQL Editor before the first run. Then use GitHub Actions → **StockPulse DSE
Dividend History** → Run workflow. For a single test, enter `AAMRANET` in the optional tickers
input. The workflow also runs daily; check its logs because the legacy DSE site may block requests
or change its HTML. The scraper skips pages where it cannot confidently parse dividend history,
so an unsuccessful scrape will not erase existing year values.

- `scrape.yml` runs DSE/CSE current prices, indices and market summary every 30 minutes during the configured Bangladesh market window.
- When the existing app/Pipedream button dispatches `scrape.yml` manually, the workflow runs CSE prices + company details, DSE prices, DSEX indices, market summary, historical DSE refresh, indicator precompute, daily closing/fundamentals, and DSE dividend history in sequence. `include_history` defaults to true.
- CSE company detail pages are not fetched during frequent scheduled price-only runs. They are fetched during a manual full refresh.
- Dividend-history scheduled refresh is now twice weekly; manual full refresh still covers all tickers.
- `market-summary.yml` and `daily-closing.yml` are manual-only to avoid duplicate scheduled runs. `update-history.yml` is shifted to 16:45 Bangladesh time.
- Shared GitHub Actions concurrency group serializes market pipeline jobs so manual and scheduled market runs do not run concurrently.

### Duplicate prevention and Supabase constraints

All market writers use PostgREST upsert with conflict keys. To prevent duplicate rows, ensure these UNIQUE constraints exist in Supabase (the upsert conflict target requires them):

- `dse_live_data (ticker, date)`
- `daily_closing_prices (ticker, date)`
- `cse_market_data (code, date)`
- `history_dse (ticker, date)`
- `dsex_index (index_name, date)`
- `dse_dividend_data (code)`

A repeated run for the same key will merge into the existing row rather than create a second row. This does not mean every network upsert is skipped; it means duplicates are prevented by the database key. Back up the database and check existing duplicates before creating constraints.

### Ticker coverage

The dividend scraper now paginates through all `dse_live_data` ticker rows rather than reading only the first 1,000. The source universe for dividend history is therefore every distinct ticker present in `dse_live_data`; a ticker absent from that table cannot be scraped by this job. Confirm the live-price scraper populates the complete official ticker universe before relying on full coverage.

### Before deploying

1. Confirm GitHub repository secrets `SUPABASE_URL` and `SUPABASE_SERVICE_KEY` are set.
2. Confirm the existing Pipedream workflow dispatches `.github/workflows/scrape.yml` via `workflow_dispatch`.
3. Confirm the Supabase unique constraints above exist and inspect any pre-existing duplicates first.
4. Run `npm install`, `npm run test:dse-legacy`, and `npm run test:dsex` in GitHub Actions or a local environment with dependencies.
5. Check the first manual run's Actions logs and Supabase row counts before treating it as production-ready.

## Certificate errors ("unable to verify the first certificate")

`cse.com.bd` and `dsebd.org` send an incomplete certificate chain. Browsers repair this automatically, Node does not. Public market pages are therefore fetched with a tolerant agent that is defined inside each scraper (`cse_scraper.js`, `dse_dividend_history_scraper.js`, `dsex_scraper.js`), so they work even if an older `scripts/lib/common.js` is deployed. Supabase keeps strict certificate verification (`httpsAgent`). Never use the tolerant agent for requests that carry secrets.

## Workflow behaviour

- The dividend-history scraper is NOT part of the manual `scrape.yml` pipeline any more. Run it from its own workflow ("StockPulse DSE Dividend History", manual or Sunday/Tuesday schedule).
- Every step in `scrape.yml` uses `!cancelled()`, so one failing source (for example CSE) no longer skips the DSE, market-summary, history, daily-closing and dividend steps. The run still ends red if any step failed, so errors stay visible.
- Dependencies are installed with `npm install --no-audit --no-fund` (there is no `package-lock.json`, so `npm ci` only printed an error before falling back).

## Dividend history scraper speed

`scripts/dse_dividend_history_scraper.js` processes tickers in parallel and only uses Chromium as a capped last resort.

| Variable | Default | Meaning |
| --- | --- | --- |
| `DIVIDEND_CONCURRENCY` | 6 | parallel tickers |
| `DIVIDEND_SCRAPE_DELAY_MS` | 120 | pause per worker after each ticker |
| `DIVIDEND_MAX_BROWSER_FALLBACKS` | 15 | Chromium launches allowed per run |
| `DIVIDEND_TICKERS` | all | comma-separated ticker list |

If DSE starts answering with HTTP 429/503, lower `DIVIDEND_CONCURRENCY` (for example 3).

## CSE scraper

Rows are saved in batches of 100 instead of one request per ticker. When a company-details page cannot be read, the stored `eps`, `pe_ratio`, `dividend`, `record_date` and `category` are left untouched instead of being overwritten with empty values.

## Automatic ticker discovery

The DSE/CSE current-price scrapers parse the symbols returned by the exchange market tables and upsert rows into `dse_live_data` and `cse_market_data`. The StockPulse app merges symbols from those tables into its in-memory ticker universe at startup and refreshes every six hours while open. No hard-coded `core.js` edit is required for symbols that are successfully published into those tables. This relies on the app's Supabase RLS allowing read access to market data. Discovery does not by itself guarantee history, indicators, dividend data, or that non-equity instruments are excluded; verify exchange category fields and the ticker coverage audit.

## Ticker-list performance and filtering (2026-10-23)

- New shared helper `scripts/lib/tickers.js`. Date-keyed tables (`dse_live_data`, `history_dse`, `daily_closing_prices`, `cse_market_data`) are read for their **latest date only**, which is about one row per instrument, instead of paginating years of history. This keeps the ticker list fast even as history grows.
- The dividend-history job builds its universe from the latest `dse_live_data` day, the latest `history_dse` day and `stock_metadata`. Set `DIVIDEND_ALL_HISTORY_TICKERS=1` to scan every `history_dse` row (slow) if delisted symbols must be included.
- Government securities (codes like `TB5Y1130`, `T10Y0128`, `BGTB...`) are skipped by the dividend job because they have no company page or dividends. Mutual funds and debentures are kept. The pattern lives in `lib/tickers.js` (`isLikelyNonEquityCode`); extend it if more instrument types should be excluded.
- `npm run audit:tickers` now finds the app's `core.js` automatically in common sibling folders (`../My-Stock-main/core.js`, `../My-Stock/core.js`) or via `APP_CORE_JS`. It uses latest-day mode by default; `AUDIT_ALL_ROWS=1` scans all rows. Filtered government securities are labelled `DATABASE_ONLY_GOVT_SECURITY_FILTERED`.
- The ignore file is now `.gitignore` (it was committed as `gitignore`, so it had no effect) and also covers `__pycache__/` and `ticker-audit-output/`. The stray `scripts/__pycache__` folder was removed.
